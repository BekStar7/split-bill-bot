# SplitCheck Bot — архитектура и идеи

Telegram-бот для групповых чатов: кто-то кидает фото счёта, бот распознаёт позиции и помогает
разделить сумму между участниками.

## 1. Продуктовые идеи

### MVP (то, что делаем первым)

- **Фото чека → структурированный счёт.** Бот скачивает фото, отдаёт в Claude Vision, получает
  JSON: позиции (название, кол-во, цена, сумма), сервисный сбор, скидки, итого. Пользователь видит
  распознанный список и может поправить любую строку одним сообщением («3 → Кальян 8000»).
- **Режим «Поровну».** Итог / число участников. Участники — все, кто нажал «Я участвую» под
  сообщением бота (или кого указал инициатор).
- **Режим «Каждый своё».** Под каждой позицией inline-кнопки; каждый отмечает, что ел/пил.
  Одну позицию могут отметить несколько человек → делится между ними.
- **Общие позиции (кальян, вода, хлеб).** Инициатор помечает позицию как «общая» —
  она делится на всех участников счёта, независимо от того, кто её отметил.
- **Сервисный сбор и скидки** распределяются **пропорционально** доле каждого в чеке,
  а не поровну (иначе тот, кто взял кофе за 1500, платит столько же сервиса, сколько тот,
  кто взял стейк за 25 000).
- **Итог в чат:** таблица «кто сколько должен», сумма сходится с чеком до тенге
  (остаток от округления — на инициатора/плательщика).

### Следующие итерации

- **Кто платил.** Инициатор указывает, кто закрыл счёт картой → бот пишет «Айдар → Беке 7 450 ₸».
- **Долговая книга чата.** Накапливать долги между людьми по чатам, `/debts` показывает нетто,
  `/settle` закрывает. Взаимозачёт: если A должен B 5000, а B должен A 3000 → A → B 2000.
- **Kaspi-ссылки.** Генерировать ссылку/текст для быстрого перевода (Kaspi Pay QR/ссылка на номер).
- **Незарегистрированные участники.** «Гость Ерлан» без Telegram-аккаунта — инициатор отмечает
  за него.
- **Позиция ×N.** Если «Пиво ×4» и его отметили 3 человека — спросить, кто сколько взял
  (по умолчанию поровну).
- **Чаевые.** Кнопка «+10 % на чай» перед итогом.
- **Мультивалюта** для поездок (счёт в USD/TRY, отчёт в ₸ по курсу дня).
- **Web App (Telegram Mini App).** Когда позиций 30+, кнопки в чате неудобны — открывать
  мини-приложение с чекбоксами. Vue/Nuxt — твоя территория.
- **История и экспорт.** `/history`, CSV в личку.
- **Личка бота.** Один человек может делить чек «с самим собой» — просто чтобы посчитать.

## 2. UX-флоу в чате

```
[Беке] отправляет фото чека в группу
[Бот]  🧾 Распознал 7 позиций, итого 42 300 ₸ (сервис 10 %)
       1. Стейк рибай          25 000
       2. Цезарь                4 500
       3. Кальян                8 000
       4. Кола ×2               1 800
       ...
       Режим: [Поровну] [Каждый своё]
       Участники: Беке          [Я участвую]

  — все тыкают «Я участвую», инициатор жмёт «Каждый своё»

[Бот]  редактирует сообщение: каждая позиция получает кнопку
       «1. Стейк рибай 25 000 — Беке»  «3. Кальян 8 000 — 🌐 общая»
       Инициатор: [⚙ сделать общей] [✅ Посчитать]

[Бот]  💰 Итого:
       Беке   — 31 350 ₸ (стейк, ⅓ кальяна, сервис)
       Айдар  —  7 150 ₸
       Данияр —  3 800 ₸
       ✔ Сходится с чеком: 42 300 ₸
```

Ключевые решения UX:

- Всё состояние счёта живёт в **одном сообщении бота**, которое редактируется (`editMessageText`),
  чтобы не засорять чат.
- Правки распознавания — через **reply на сообщение бота** в свободной форме («2 → 4 700»,
  «удали 5», «добавь Чай 1200»). Парсим регулярками, при провале — через LLM.
- Callback data лимитирована 64 байтами → кодируем `b:<billId>:i:<itemIdx>:t` (toggle),
  все идентификаторы короткие (nanoid 8).

## 3. Доменная модель

```ts
Bill {
  id, chatId, messageId, createdBy, createdAt
  status: 'draft' | 'assigning' | 'done'
  mode: 'equal' | 'itemized'
  currency: 'KZT'
  items: BillItem[]
  serviceFeePct?: number        // 10 → 10 %
  serviceFeeAbs?: Money         // если в чеке абсолютной суммой
  discountAbs?: Money
  tipPct?: number
  total: Money                  // как в чеке — для сверки
  payerId?: UserId
}

BillItem {
  idx, title, qty, unitPrice: Money, amount: Money
  shared: boolean               // делится на всех участников
  claimedBy: UserId[]           // кто отметил (в itemized-режиме)
}

Participant { billId, userId, displayName }

Settlement {                    // результат расчёта, хранится для истории/долгов
  billId, userId, amount: Money, breakdown: Line[]
}
```

**Деньги** — целые числа в минимальных единицах (тиын/копейки), никакого `number` с дробями
в расчётах. Для ₸ по факту работаем в тенге, но храним `amountMinor` на будущее.

### Алгоритм деления (`core/split.ts`)

1. Базовая доля каждого участника:
   - `equal`: `subtotal / n`.
   - `itemized`: для каждой позиции — если `shared` → `amount / n` каждому; иначе
     `amount / claimedBy.length` каждому отметившему. Никто не отметил → позиция считается
     общей (и бот об этом предупреждает).
2. Сервис / скидка / чай — пропорционально базовой доле: `share_i * (fee / subtotal)`.
3. Округление до целой единицы методом **наибольших остатков** (largest remainder) — сумма долей
   ровно равна итогу чека, никто не переплачивает больше 1 ₸.
4. Возвращаем `Settlement[]` с breakdown для объяснения «почему столько».

Ядро — **чистые функции без I/O**, покрыты unit-тестами. Это самая ценная часть, её нельзя
сломать.

## 4. Техническая архитектура

```
Telegram ──long polling / webhook──▶ grammY bot
                                        │
                     ┌──────────────────┼──────────────────┐
                     ▼                  ▼                  ▼
              handlers/           services/           core/
         (commands, photo,    (bill lifecycle,     (split algorithm,
          callbacks, edits)    rendering, OCR)      money utils)
                     │                  │
                     ▼                  ▼
              repo/ (SQLite)     ocr/ (Claude Vision)
```

- **Runtime:** Node 22, TypeScript, ESM.
- **Bot:** [grammY](https://grammy.dev) — типизированный, middleware-based, есть плагины
  `conversations`, `menu`, `runner`.
- **OCR:** `@anthropic-ai/sdk`, модель с vision, structured output через tool-use — получаем
  строго типизированный JSON, валидируем через `zod`.
- **БД:** SQLite через `better-sqlite3` + `drizzle-orm` (типизированные схемы, миграции).
  Один файл, монтируется в volume.
- **Конфиг:** `.env` → `zod`-валидация при старте, падать сразу, если нет токена.
- **Логи:** `pino`.
- **Тесты:** `vitest`.
- **Деплой:** multi-stage Dockerfile, `docker compose up -d` на VPS. Long polling в MVP
  (не нужен домен/HTTPS), webhook — когда появится домен.

## 5. Открытые вопросы

- Как отмечать за человека без Telegram (гость)? — inline-кнопка «+ гость» у инициатора.
- Что делать, если в чеке «Пиво ×4», а отметили 3 человека? — MVP: поровну; потом — диалог.
- Хранить фото чека? — Нет, только `file_id` Telegram (можно перекачать по нему).
- Права: кто может менять режим/общие позиции? — MVP: инициатор + админы чата.
